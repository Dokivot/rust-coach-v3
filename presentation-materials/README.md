更新日期：2026-11-05。本目录保存可改写的内容与证据，供后续使用 ppt-master 统筹制作项目 PPT；目前没有设计规格、页面锁定、PPT 文件或正式逐页讲稿。

## 项目与整体流程

Rust Coach 面向 Rust 生存游戏玩家，帮助他们根据库存、目标和当前处境，判断制作资源缺口、拆除条件及下一步行动。本文中的 Rust 指游戏，不是编程语言。

用户提出问题并按需上传截图 → 系统理解任务与有效玩家状态 → 使用规则计算或检索证据 → 返回带条件的结果 → 用户补充血量、库存等信息后继续追问。效果验证在独立评测流程中检查这些回答，不是每次聊天都会自动运行一整批评测。

## 统一业务术语

| 术语 | 本材料的含义 |
|---|---|
| C4／定时炸弹 | 游戏中的制作目标；不要与中间材料“炸药”混称 |
| 电子零件 | 案例中的 tech trash；与图中的齿轮是不同物品 |
| 图像观测 | 模型从截图提取的物品、数量和归属候选；属于推断，不自动成为事实 |
| 有效库存 | 当前问题允许采用的库存信息；历史、他人或过期观测不得直接抵扣 |
| 抵扣 | 计算材料缺口时减去可用物品；不会消耗真实游戏背包 |
| 局部库存 | 只知道一部分物品；未展示或未知不等于数量为零 |
| 独立标注／金标 | 人工确认的图像标签与独立配方依据；版本未核实的部分仍有边界 |
| 案例／运行／轮次 | 案例是一段固定任务；运行是一次执行；轮次是其中一次用户请求及回答 |
| 保存结果重判 | 对已捕获输出重新运行判定器；不重新调用模型或执行应用 |
| 首个有证据的分歧 | 按轮次及检查依赖定位的最早错误点；不等于经过干预实验证明的因果根因 |
| 待核验 | 证据尚不足以确认结论；既不当作通过，也不自动算已证实的业务错误 |
