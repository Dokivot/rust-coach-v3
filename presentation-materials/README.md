更新日期：2026-11-05。本目录保存可改写的内容与证据，供后续使用 ppt-master 统筹制作项目 PPT；目前没有设计规格、页面锁定、PPT 文件或正式逐页讲稿。

## 项目与整体流程

Rust Coach 面向 Rust 生存游戏玩家，帮助他们根据库存、目标和当前处境，判断制作资源缺口、拆除条件及下一步行动。本文中的 Rust 指游戏，不是编程语言。

用户提出问题并按需上传截图 → 系统理解任务与有效玩家状态 → 使用规则计算或检索证据 → 返回带条件的结果 → 用户补充血量、库存等信息后继续追问。处理过程记录耗时与调用，用户可按需查看；效果验证在独立评测流程中检查这些回答，不是每次聊天都会自动运行一整批评测。

## 依赖与去重

G07 复用 G01 的任务分流、G02 的确定性计算、G05 的库存有效性与多轮状态；G06已实现固定包采用与失效机制，真实游戏build认证仍是部分结论的前置缺口。G07为G04提供错误定位与未来修复验收依据，其历史真实样本可作为G08后续采样参考，不能替代当前版本性能基线。G08沿用这些业务边界，为各目标提供逐次调用与阶段耗时记录；目前主证据是合成模型的真实应用接口回归。

展示主线采用“截图制作→切换拆墙→补250血→追问依据→撤回后停止采用”，单格纠正、死亡、新会话与工作台是补充案例。G01讲当前任务，G05讲可用玩家事实，G02讲取证和推导，G06讲采用资格和失效，G07讲如何判断结果正确。原G01/G05共享验证表只展示一次：历史193项定向测试包含40案例/54轮固定集，另有审查版6轮真实文本冒烟；不能重复相加。G02/G06共享24案例与同一批本地接口样例，也不能相加为48例或两批独立样本。

最终 PPT 中，项目用户流程、输入—理解—知识—决策—生成—评测与观测六层、截图接入方式、计算器和状态模型各介绍一次即可。G07重点解释“如何判断这些环节有没有答对”，G08解释“等待和资源使用如何核对”，不重复介绍整套业务架构。G08复用原有缓存和本地计算，不将零模型路径包装为本轮优化；33条合成报告、测试内同样例及其他目标的共享案例不重复累计为独立证据。PPT不能把本材料的局部评测和本地计量画成已建成的全项目生产观测平台。

## 统一业务术语

| 术语 | 本材料的含义 |
|---|---|
| C4／定时炸弹 | 游戏中的制作目标；不要与中间材料“炸药”混称 |
| 电子零件 | 案例中的 tech trash；与图中的齿轮是不同物品 |
| 图像观测 | 模型从截图提取的物品、数量和归属候选；属于推断，不自动成为事实 |
| 有效库存 | 当前问题允许采用的库存信息；历史、他人或过期观测不得直接抵扣 |
| 抵扣 | 计算材料缺口时减去可用物品；不会消耗真实游戏背包 |
| 局部库存 | 只知道一部分物品；未展示或未知不等于数量为零 |
| 独立标注／金标 | 人工确认的图像标签与独立配方依据；版本未核实的部分仍有边界 |
| 案例／运行／轮次 | 案例是一段固定任务；运行是一次执行；轮次是其中一次用户请求及回答 |
| 保存结果重判 | 对已捕获输出重新运行判定器；不重新调用模型或执行应用 |
| 首个有证据的分歧 | 按轮次及检查依赖定位的最早错误点；不等于经过干预实验证明的因果根因 |
| 待核验 | 证据尚不足以确认结论；既不当作通过，也不自动算已证实的业务错误 |
| 任务动作 | 新建、继续、更正、切换、取消或澄清；决定参数继承与执行方式 |
| 任务工作状态 | 本会话保存的目标、参数与证据引用；可随对话恢复，不等于跨会话通用任务平台 |
| 持久档案 | 按服务器/清档隔离的玩家事实和容器盘点；关联后可由新会话复用 |
| 临时事实 | 有来源和有效期的明确自报，本轮可用但不隐式覆盖档案 |
| 明确空背包／未知库存 | 完整空清单是明确零库存；没看见、未盘点、过期不是零 |
| 状态事件回执 | 明确事件已持久化的记录；回答失败也保留，用于同请求幂等重试 |
| 脚本化评测／真实冒烟 | 前者固定模型与图像输出以检查工程链路；后者少量真实模型调用，只证明样例表现 |
| 固定快照／游戏build | 前者是本项目选择的资料范围；后者是实际游戏构建版本，当前未独立认证 |
| 知识发布包 | 一份不可变的规则引用、说明与摘录集合；安装候选和启用是不同动作 |
| 发布引用 | 包ID、内容hash、登记修订号；用于识别结果依赖及失效 |
| 证据采用资格 | 范围、状态与撤回检查；检索相关不等于允许采用 |
| 规则依赖闭包 | 一次计算依赖的配方和目标记录，任何必要记录失效都应停止发布结果 |
| 全文解释检索 | 在已整理主题与片段中做词法检索；不等于通用语义推理或自动证明 |
| 请求／运行尝试／任务 | 请求标识可用于重试或重放；每次尝试有独立run；业务任务可跨多轮延续，三者不等同 |
| 实际阶段／进度事件 | 前者包围真实工作并计时，可能嵌套重叠；后者通知当前状态，首条进度不等于有效答案 |
| 模型尝试／发送标记 | 入口尝试次数与到达HTTP发送边界分别记录；发送不证明供应商接收或收费 |
| usage／账单 | usage是返回的token用量；账单需要价格与供应商依据，缺失不能当作零费用 |
| 已知合计与覆盖率 | 合计只包括已报告的有效数值，并说明报告该字段的调用数／总调用数 |
| 前台／后台 | 前台处理本轮回答；后台独立运行并关联原请求，可能重叠，耗时不能直接相加 |
| 应用复用／供应商缓存 | 前者复用有效观测或结果，后者是供应商usage里的cached明细，不混称同一种命中 |
