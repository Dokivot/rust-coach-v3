# 六层架构受控迁移验收

本文件冻结两条 Demo 端到端验收案例。每个阶段必须证明输入、理解、决策、生成和观测之间的边界与关联；未通过当前阶段不得进入下一阶段。

## 强计算案例

用户请求明确的合成缺口或拆墙数量。输入层生成 `ParsedInput`，理解层选择 `simple_call`，决策层只调用确定性 Calculator，生成层只能渲染工具结果，观测层记录同一个 `trace_id` 下的各层事件。模型不可自行计算数字，缺失槽位必须返回 `needs_input`。

## 状态建议案例

用户提出“根据当前状态先加固还是冲科技”等建议请求，并已绑定玩家状态档案。输入层生成请求候选，理解层选择 `plan_execute`，决策层经过有限 Planner/Executor/Verifier 流程，读取状态和必要证据，生成首选、替代、前置条件、完成标准和切换条件。生成层不得接收或展示内部 `ExecutionPlan`，观测层记录计划摘要、工具调用、状态 revision 和结果状态。

## 共同门禁

- 两条链路都使用版本化层间协议和同一任务生命周期。
- `DecisionResult` 是生成层唯一业务输入；失败必须保留真实状态。
- 计算和建议工具均为无副作用、可校验、可追溯调用。
- 观测事件不得写入原始图片、完整私人记忆或模型思维链。
- 旧 API 和既有测试保持兼容，迁移通过后才清理旧分支。
