# 截图输入首版：实际实现与验证

实现日期：2026-11-02，PC 原版规则集。运行模型为用户配置的 `gpt-5.6-sol`，通过 `https://cf.api.fan/v1` 的 Responses 接口访问。没有把模型名称当作视觉能力证明；必须先通过双图随机数字探测。探测只证明图像传输、文字读取、图序和结构化响应，不能证明 Rust 图标或布局判断准确。

## 使用方法

1. 在聊天框上方展开“截图”，选择、粘贴或拖入最多四张 PNG/JPEG/WebP，即可发送。不需要填写时间，也不会强制打开裁剪弹窗。首次发送会自动运行视觉接口探测；已通过的配置不重复探测。
2. 可以只发图片，也可以附材料缺口、基地局部或装备问题。模型结合当前问题、最近四条相关用户消息和玩家状态判断截图上下文。无相反说明时默认当前本人；旧图、参考图、对手或队友可直接在消息中说明。
3. 识别结果直接出现在回复中。可支持的计算或建议立即执行，无需逐项勾选确认。时间未填写时使用上传时间作为假设，不声称这是实际拍摄时间。
4. 当前本人、单图单容器、完整视图、物品与数量明确、槽位不重复且无歧义时，自动库存可用于缺口计算。局部、旧图、他人或读数未知仍展示识别结果，计算给总需求；不会把未知值补成零。模型完整性判断与读数仍可能出错，工具保证的是给定输入的计算正确。
5. “查看识别详情与图片区域”默认折叠。需要时展开查看区域，或进入“修正识别 / 保存到档案（可选）”。“应用修改”只用于任务；“保存到本人档案”要求已关联档案且属于当前本人。自动识别不会覆盖长期档案。
6. 裁剪、遮盖及“补充主体或时间（可选）”保留在附件旁。图片到发送时才上传并进入所配置的模型服务。

续问出现旧图、本人、对手等上下文修正词时，重新结合图片与近期对话理解，生成新草稿；保留原观测时间，不通过续问延长库存有效期。其他续问可复用原草稿。人工修改后的再次纠错可重发图片或更新状态页。混合主体的多图可以作条件分析，不合并为本人库存。

## 模块边界

| 模块 | 实际职责 | 不承担的职责 |
| --- | --- | --- |
| `attachments/` | 解码、归一化、私有文件、哈希、访问归属、过期与删除 | 物品识别、玩家状态修改 |
| `vision/schemas.py` | 候选观测、区域坐标、任务与确认契约 | 证明像素内容正确 |
| `vision/context.py` | 主体/时间默认与显式覆盖、自动输入、完整库存门槛 | 伪造人工确认、证明截图真实性 |
| `vision/service.py` | 有界 LangGraph 感知子图、缓存、复读、草稿、业务输入门槛 | 游戏数值推导、自动保存 |
| `vision/drafts.py` | 草稿 CAS、确认幂等、时效/范围/主体、事务回执 | LLM 调用、长期锁等待 |
| `runtime.py` / `workflows.py` | 单任务执行、超时、路由、确认后的新请求、结果持久化 | 把所有业务规则塞入 Graph |
| `calculations/` | 校验输入、配方展开、拆墙数量、缺口、条件和规则来源 | 证明图像读数正确、战斗模拟 |
| `advice/` | 候选规划、网页取证、工具预算、条件建议与图片区域引用 | 从局部图补全隐藏基地或凭装备算胜率 |
| `player_state/` | 显式保存的观测、revision、TTL、事件失效与历史 | 自动继承别服/旧清档状态 |
| `presentation/` | 统一人设、受保护报告与图片范围、最终时效检查 | 改写工具数值、把引用匹配说成事实认证 |
| `static/vision.js` | 直接发送、自动探测、可选预处理/修正/保存、区域定位 | 在浏览器保存模型密钥 |

## Graph 与执行控制

主图进入 `visual_input`：无图片直接走原链路；新附件进入视觉子图；已有草稿按 ID 恢复证据。图片 Base64 只在模型调用的消息中临时构造，不写入 Graph State、Turn 或 SQLite 草稿。

视觉子图：`prepare → extract → validate → [refine → validate] → persist → END`。缓存命中跳过 `extract`。首次 JSON/业务 Schema 失败允许一次结构修复，修复请求包含具体字段错误；这会消耗与局部复读共享的修复预算。局部复读最多四个歧义数字区域，只更新合法整数读数。图 recursion_limit=10，主图为 12；没有无限自主工具循环。

提取的 task 用于分流：`observe` 直接输出识别，`craft/raid` 自动调用计算器，`advice` 基于可见范围给条件建议。模型不负责计算。自动截图库存优先于已选择的档案库存，明确的文本库存可覆盖自动读数；不把两个来源相加。`/calc JSON` 的纯文本路径仍是确定性捷径，不增加视觉调用。

显式 `/coach`、`/search` 优先于视觉 task 提示。同一新图请求不混用 `/calc JSON`：带图时用自然语言描述目标，或单独发送精确命令，避免重新解析覆盖参数。

普通路径在识别后直接执行到 END，没有等待确认节点。可选人工修改采用持久草稿与新请求继续。没有使用 LangGraph 原生 `interrupt()` 或 Checkpointer，因此任意中间节点崩溃重放仍未实现。草稿、成功轮次与可选确认回执可重启恢复；识别成功而业务失败时，原 request_id 重试复用草稿。

可选修改/保存事务包含：校验原草稿 revision、绑定档案及原 revision → 校验全部 accepted/excluded 项 → 可选状态更新 → 消费草稿 → 保存幂等回执。SQLite `BEGIN IMMEDIATE` 保证整体提交或回滚；生成回复在提交之后执行。

## 状态、知识与时效

- 单次任务：Graph State 存引用与小型 JSON。自动结果放在 `payload.automatic` / `Turn.visual.automatic`，标记 `source=image_inferred`、`confirmation_id=null`、`confirmed=false`、`usable=true`。只有真实人工修改才有 accepted receipt；两者都可供任务使用，不自动成为长期记忆。
- 跨轮：`Turn.visual` 存附件元数据、观测、确认状态、草稿与版本引用；历史回复保持当时快照，不随确认修改原文。
- 跨会话档案：显式 `save_to_profile` 写入 `visual_observations`，以 `attachment_id:observation_id` 为键，保留来源 `image_confirmed`、原图哈希、时间、草稿 ID。没有另外引入设备/基地专用存储层；局部描述不写入全局 `base.*` 事实。
- 保存窗口及任务库存 TTL 为 30 分钟；档案中的基地局部观测 TTL 为 120 分钟，其他视觉观测为 30 分钟。未填时间以服务端上传时间冻结计时；填入时间时使用该时间。新确认不能刷新旧截图，历史/参考上下文不得保存为当前状态。
- 死亡、被袭击等事件会失效相关视觉记录；失效时间水位阻止旧图再次覆盖为当前状态。档案 revision 改变时，旧草稿不再用于当前精确库存。
- 更新时剔除过期/失效的当前视觉记录，历史观测仍在版本日志；当前集合最多 240 条。状态页和 `/state` 能查看图片来源与时效。
- 普通对话最多注入前 20 条视觉观测，建议规划/生成最多 24 条并标明省略数量；计算使用完整结构化库存，不使用被截断的模型上下文求数。
- 图像缓存按会话、规范图哈希、问题、图像上下文、近期用户上下文、玩家状态、模型/接口/detail/提取版本和目录哈希分键；24 小时失效。命中不会刷新原图时间；重复图片不相加。当前提取版本为 `visual-observations-v3`。
- 图片只作为私人观测证据，不进入公共机制知识库。配方与伤害仍使用原有固定数值快照，截图接入不会修复该快照尚未核验游戏 build 的限制。

## API 与配置

| API | 输入/用途 |
| --- | --- |
| `POST /api/conversations/{id}/attachments` | 单个 multipart `file`，返回 UUID、尺寸、SHA256、访问地址、到期时间 |
| `GET /api/conversations/{id}/attachments/{image}` | 原图；`?thumbnail=true` 取缩略图 |
| `DELETE /api/conversations/{id}/attachments/{image}` | 删除文件并使关联草稿不可继续，清除该会话视觉缓存 |
| `POST /api/vision/probe` | 配置指纹对应的双图随机数字探测 |
| `POST /api/conversations/{id}/messages` | 原有字段 + `attachment_ids`、每图 `image_context`，或 `visual_draft_id` |
| `GET .../visual-drafts/{draft}` | 当前草稿、revision、available、候选及回执 |
| `POST .../visual-drafts/{draft}/confirm` | `confirmation_id`、双 revision、逐项 edits、主体/时间/范围、用途、可选 calculation |
| `POST .../visual-drafts/{draft}/cancel` | 取消未确认草稿，不撤销已经保存的档案 |

`COACH_VISION_ENABLED` 默认 true；`COACH_VISION_MODEL / BASE_URL / API_KEY / API_MODE` 对应的完整环境变量名分别为 `COACH_VISION_MODEL`、`COACH_VISION_BASE_URL`、`COACH_VISION_API_KEY`、`COACH_VISION_API_MODE`，未配置时继承主模型配置。`COACH_VISION_DETAIL` 默认 high，输出上限至少 8192 token。密钥只在本地 `.env` 配置。

默认每图 8 MiB、20M 像素、边长 8192；拒绝动画、伪图片与解码炸弹。浏览器预处理和服务端均有检查。使用实际解码格式而非客户端 MIME 判定。附件重编码剥离 EXIF，目录 0700、文件 0600。原图默认保留七天，草稿一天；到期立即拒绝访问，物理文件在启动和后续上传时清理。全局规范图配额 256 MiB，不含缩略图开销。

删除原图不撤销已确认的玩家自报观测，也不会从历史回复中抹除读数；需要让当前状态失效时使用状态事件或新观测。删除会话会清除附件、该会话草稿和缓存，已单独保存的玩家档案保留。系统仍仅适用于本机单用户，附件归属检查不是多用户认证方案。

## 验证与真实边界

自动化测试覆盖两种上游协议的图像编码、归属/删除/文件丢失、字节与像素限制、动画拒绝、能力门控、缓存/重复图、草稿持久恢复、确认 CAS 与回滚、重复确认、失败续问、空完整库存、局部堆叠不写总量、跨主体/时间/容器保护、基地/装备保存、事件水位、旧库存不继承、建议预算读取临时确认库存。运行 `uv run pytest -q`；浏览器脚本通过 `node --check`。

真实模型测试记录见 [验证报告](multimodal-verification.md)。实测发现并修复了两类问题：合成结果误填拆墙 `target` 导致 Schema 拒绝，以及单行工具柜裁图被误判 full_view。修复后同样例通过，不代表同类错误已完全消失。

可运行 `uv run python docs/run_vision_smoke.py 图片路径 --question '问题' --output data/vision-eval/result.json` 重新测试。`--workflow` 运行完整聊天/建议图并关闭网页检索，用于检查纯观察降级。脚本使用临时数据库，不修改真实玩家档案；它会将指定图片发送给配置模型并产生费用，输出中包含该测试图的识别文字。

当前默认自动识别并使用，人工修正是可选能力。**尚未完成设计中的 300 图/60 任务标注评测，不能宣称识别准确率、p95 或单次成本达标。** 模型可能错读图标、数字、完整性和空间关系；自动计算结果以识别输入为条件，代码校验不能证明像素读数正确。基地只支持可见局部与有依据的条件检查，装备没有精确伤害/TTK/胜率计算。机制断言仍受现有语义校验能力限制。

预算是节点调用次数与时限控制，并非跨多个失败续问的累计 token 钱包。首次视觉任务通常一次 VLM，修复/复读最多再一次；建议还可使用原有规划/生成与一次修复。重复成功确认可零新增调用回放；失败重试可能再次调用后续模型。日志只记录草稿 ID、耗时、修复次数、缓存与错误类型，原图和 Base64 不进入日志。
