## 十项审查结论

| 审查项 | 判断与证据 |
|---|---|
| 1. 真正实现还是表面功能 | 已实现运行、模型尝试、网页请求、阶段、持久化及用户入口。真实速度／费用可接受未证明，两层完成度必须分开 |
| 2. 端到端流转 | 文字／附件→runtime→节点／模型span→HTTP／usage→业务提交→计量终态→API→回复详情。上传、探测独立，后台有origin_run_id，重放新run零调用。浏览器点击至渲染尚无统一交互ID |
| 3. 决策输入与约束 | 沿用有效玩家状态、视觉来源及失效检查、知识版本校验和确定性计算。记录角色、模型与输出上限；保留原超时、局部修复上限；没有价格依据，Agent不自行做金额最优调度 |
| 4. 推断与事实 | 视觉提取与建议是模型候选，采用受计算及证据校验约束。usage是供应商报告而非账单，dispatched是发送边界而非供应商接收证明；injected与provider区分，cached/reasoning不重复相加 |
| 5. 静默失败与伪成功 | 已修复交付缺失通过、流用量丢失、重启完整性误报和后台提前成功。invalid/missing usage不补零；API读取失败显式报错。完整性声明只覆盖返回窗口，不能重建全库丢失的历史 |
| 6. 异常降级 | 计量失败不替换业务答案；传输、取消、超时、限流保留已知消耗。失败不保存成功轮次，释放锁可重试。修复有局部上限，不用未经验证答案换取速度 |

## 剩余限制和真实验收方案

1. **真实速度与金额未验证**。没有确认的阈值，不能自行把某秒数／金额写成达标线。下一轮先按普通问答、截图与建议确定目标，再固定模型、设备、网络、画质、数据集及并发条件，记录点击到有效答案、上传／探测、超时率、质量通过率、usage覆盖率和账单。20次只是当前工具输出p95的最低门槛，并不代表结论稳健。
2. **没有共享请求预算**，遵循明确约束。普通请求90秒、建议180秒、取证25秒、记忆20秒是默认配置，局部上限不能相加成用户等待承诺，也不证明整次费用有上限。单runtime锁串行化，忙时409；未做生产负载测试。
3. **费用未知不等于免费**。缺usage及取消不能还原最终账单；cached/reasoning为子集。模型尝试、HTTP发送、成功返回和业务采纳是四件事。流收集仅代表最后一次已收到的usage，不承诺供应商最终清算值。
4. **计量不是可靠消息账本**。持锁时放弃写入并报incomplete；进程内故障标记保守影响后续汇总直到重启。v2的span_count发现缺span，不能发现整条run从未落盘或全部被删除；v1不能补做计数认证。数据库不可读时API失败；没有durable outbox或保留期平台。
5. **耗时有边界**。run／span的duration在自身终态落库前截止，不包含最后一次自身写入。父子span、父子run及前后台可重叠，不能相加。TestClient缓冲SSE不能测浏览器首个有效答案，进度不是答案。计量不等SQLite锁，但连接、序列化、磁盘I/O及业务自己的5秒锁等待仍可能阻塞事件循环。
6. **质量证据有限**。合成图与模型不检验真实识别、开放问题或最新Rust规则；既有知识撤回／版本保护保留。固定数值是已收录快照的回归，非独立游戏专家认证。没有改模型、图像细节或缓存有效期，也没有跳过校验来追求速度。

## 五个面试追问与建议回答

**1. “怎么证明用户等得起、成本可接受？”**

目前不能证明真实达标。已完成从请求、模型／网页、保存到交付的可归因计量与故障验证。合成评测仅验证流程和次数。真实验收需事先定义分场景目标，在同一质量门槛下采集端到端耗时和账单，不用超时配置代替用户体验。

**2. “为什么一次工具调用可能有更多账单？”**

内部修复、视觉探测和后台记忆会另调模型。我逐complete计量，用角色和parent_run_id关联，同时记录发送标记与usage覆盖率。超时后供应商可能已计费，缺失保持未知，金额仍需账单核对。

**3. “零调用和缓存是否牺牲正确性？”**

只复用有效观测、状态和已有回答；计算采用当前目标／血量，知识撤回会拒绝旧结果重放。冷图、热图、切换目标及血量追问同时断言结果与次数。缓存是已有能力，本轮未包装成新算法，更不会降低校验标准。

**4. “33/33会不会系统自己给自己打分？”**

这是11种合成场景的工程回归，不是33名真实用户。我增加独立夹具账本、返回与保存一致性、固定数值结果、重放副作用检查。拿掉最终答案后旧评测仍全通过，新的会失败；这证明这些边界受到检查，不能证明开放问题整体准确率。

**5. “计量自己故障／进程崩溃怎么办，为什么不用追踪平台？”**

原计量会等数据库锁拖慢回答，现在计量写不等待锁，不覆盖业务答案，可读报告明确incomplete。running与span数可发现部分中断，全程没落盘无法恢复。当前本地单进程不必引入分布式平台；未来若要求审计级完整性或并发SLO，再按实测瓶颈引入独立持久队列和采集器。
