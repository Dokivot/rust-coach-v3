# 自然短答与可展开详情

本次调整解决计算和建议回复逐项打印内部字段、默认展示冗长报告，以及前端丢弃 `detail` 块的问题。

## 用户可见行为

默认先回答问题，再保留影响行动的条件。例如，制作一百个火药、提供一百硫磺和一百五十木炭库存的测试请求，现在显示：

> 按你提供的库存，制作 100 火药 还差 100 硫磺、150 木炭。需要 1 级工作台，你提供的等级满足要求。配方方面，你提供的清单包含所需配方。
>
> 依据为 PC 原版资料快照，未核验游戏 build，未经游戏内实测。

计算步骤、已抵扣库存、批次数、来源和计算凭据放在“查看计算、观测与来源详情”中。用户要求详细说明时，原始报告直接展示。

建议将经过校验的理由、取舍、前置条件、步骤、完成标准和停止条件组合为段落，不再逐项打印“行动／理由／取舍／下一步”等标题。空的补充信息不展示，完全相同的句子去重。选中方案的预算紧随对应建议；未选中方案的预算保留在详情中。简短模式将理由与取舍移入详情，但保留前置条件、行动和停止条件。

截图计算先显示缺口，截图识别列表放入详情。当前本人假设、过期或主体范围、画质提醒、未知项仍显示在正文；单纯要求识别图片时继续显示观测列表。

## 实现与事实保护

- `presentation/rendering.py` 从计算器结果直接生成数值句子；建议仅组合已通过检查的字段，不增加模型润色调用。数量、可行性、候选选择、证据和原始计算结果继续保存在受保护数据与断言中。
- 未知库存不写成实际缺口，局部截图保留覆盖限制，材料齐全不代表工作台或配方已满足。过期状态、拒绝不受支持的确定性描述、修复次数上限继续生效。
- `Turn.assistant` 保存正文；`Turn.presentation.blocks` 保存正文和完整详情。后续聊天历史使用短答，刷新或重启后仍能从已保存的详情块查看依据。
- 前端使用原生 `details/summary`，所有内容通过 `textContent` 写入，保留浏览器提供的键盘操作与折叠语义；旧版无 presentation 数据的消息仍可显示。
- renderer 版本更新为 `coach-render-v2`。`AnswerSpec` 仍是架构适配记录；本次表达改造作用于现有结果呈现链路，没有将它重构成独立的模型生成输入。


本次离线验证为 382 项 Python 测试、3 项前端 DOM 回归全部通过，JavaScript 语法和 diff 检查通过。覆盖自然短答、默认与详细模式、数值和前置条件、未选预算、截图覆盖与画质提示、持久化及追问历史、详情内容安全、英文标签和旧消息兼容。

前端测试使用最小 DOM 替身验证渲染结构和文本安全，并未模拟真实浏览器的键盘事件。未调用付费模型进行自然度评审。实时评测增加自然表达、结论先行、追问不重复三个维度，并将已有对话提供给评审；规则检查与模型评审都不等于事实语义证明。
