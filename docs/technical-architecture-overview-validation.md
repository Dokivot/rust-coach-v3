交付为一张 [核心架构 SVG](technical-architecture-target.svg)，不需要组合多图或关系索引阅读。按最新要求保留核心职责、主要协作与状态，具体接口、算法、函数和异常分支由 [技术设计文档](technical-design.md) 解释。

## 粒度与结构

- 六层严格按输入、理解、知识、决策、生成、评测与观测从上到下排列。
- 每层 3 个核心模块，共 18 个；两侧另有 6 个关键存储/外部依赖。每个模块仅名称、类型/状态和一句职责。
- 28 条主要关系，另有 2 条图例线。删除此前 62 节点、159 关系版本的细节索引、函数和内部处理步骤。
- 主链路突出请求、归一化输入、任务参数、任务结果和最终回答；精确计算与检索作为按需调用的知识能力。
- 蓝色表示确定性组件，紫色表示生成式组件；绿色实框/橙色虚框表示当前/目标。灰色点框保留在图例，不为未定型领域能力增设节点。
- 当前“任务规划”仅指受限候选和行动计划；完整任务步骤、预算、澄清恢复明确归入橙色“持久任务协调”。
- 当前局部日志/回归与目标全链路观测区分。全链路事件通道代表横向观测职责，不暗示目前已具备完整成本账本。
- 模型服务共享调用、状态存储共享读写及任务存储依赖用功能组说明，避免重复连线。

## 重建

```sh
python3 docs/diagrams/build_architecture.py
node docs/diagrams/validate_architecture.cjs <node_modules目录> <Chrome可执行文件> <输出目录>
```

工具目录需要 Puppeteer，本次复用临时安装，不修改项目依赖。脚本输出实际截图和 `architecture-qa.json`；布局与状态清单见 [architecture-manifest.json](diagrams/architecture-manifest.json)。总览原生 SVG 以该脚本为编辑源，旧 Mermaid 不能用于覆盖它。

本次只修改图表和文档，未改业务实现；没有为低影响的文档调整重复运行业务测试。已有软件回归结果保留在 [原始验收记录](technical-design-validation.md)。
