# 实时执行阶段

聊天等待区显示当前阶段，以及本轮已经经过的步骤。阶段由实际执行位置上报，使用固定的中文短名称；不按计时器轮播，不展示模型内部推理，也不虚构进度百分比。

## 阶段命名

| 标识 | UI 文案 | 实际触发点 |
| --- | --- | --- |
| `context` | 正在读取上下文 | 加载会话、玩家状态与记忆 |
| `image_context` | 正在读取截图信息 | 处理新附件或复用已有视觉草稿 |
| `recognize_image` | 正在识图 | 调用视觉模型提取截图内容 |
| `check_image` | 正在核对识图结果 | 校验视觉抽取结果 |
| `refine_image` | 正在复核模糊读数 | 视觉子图重读模糊数量 |
| `understand` | 正在理解问题 | 路由或解析计算请求 |
| `plan` | 正在规划方案 | 建议链路生成候选行动 |
| `retrieve` | 正在查找资料 | 调用资料检索服务，可能包含缓存读取 |
| `evaluate` | 正在比较方案 | 检查候选的状态与可行性 |
| `calculate_craft` | 正在计算资源缺口 | 调用合成计算器；库存未知时仍仅计算总需求 |
| `calculate_raid` | 正在计算拆除成本 | 调用拆建筑计算器 |
| `compose` | 正在组织语言 | 模型生成叙述或代码组织计算报告 |
| `check_answer` | 正在核对回答 | 表达或受保护事实检查，不代表游戏规则已实测 |
| `player_state` | 正在读取玩家状态 | 显示状态档案 |
| `memory` | 正在处理个人记忆 | 执行显式记忆命令 |
| `save` | 正在保存结果 | 保存成功轮次 |
| `replay` | 正在恢复已有结果 | 同一请求 ID 的成功结果回放 |

附件上传仍显示前端本地的“正在上传图片…”，请求发出后、尚未收到阶段事件时显示“正在等待处理…”。后端接手后用实际阶段替换等待文案。连续相同阶段去重；修复或重新执行可能再次进入同一阶段。

例如，截图合成通常经过“读取截图信息 → 识图 → 核对识图结果 → 理解问题 → 计算资源缺口 → 组织语言 → 核对回答 → 保存结果”。普通对话不会显示识图或计算，无需取证的建议不会显示查找资料，命中识别缓存不会假装重新识图。快速步骤不人为延时；已经过的步骤在等待区保留，最终回答返回后替换等待区。本次不将这份临时阶段列表保存到历史消息，持久 trace 仍沿用原有记录。

## 传输与异常

沿用 `POST /api/conversations/{id}/messages`。未要求事件流的客户端继续获得原有 JSON `Turn`；聊天前端发送 `Accept: text/event-stream`，通过 Fetch 读取同一响应流。

流中包含三类 JSON 数据帧，每帧均有 `request_id`：

- `stage`：包含固定的 `stage`、`label` 和递增 `sequence`。
- `result`：包含已保存的完整 `turn`，正文仍在完成后一次展示。
- `error`：包含错误代码、用户可见说明和状态码，终止本轮等待。

等待时每十五秒发送心跳注释，响应设置 `X-Accel-Buffering: no`。阶段上报使用请求范围的 ContextVar，支持 LangGraph 同步节点在线程中上报，不在共享 Runtime 上保存某一用户的回调。界面处理跨网络分片的 UTF-8、换行边界、重复序号，并核对请求 ID。

流开始前的参数或同源校验仍返回 HTTP 错误；流开始后的业务失败使用 `error` 帧。没有收到 `result` 就断流时，前端恢复原文字和截图；内容未变的重试复用请求 ID 与上传附件。服务端在连接取消时取消本次未完成的处理并释放锁；若结果已落库而客户端未收到，重试走成功回放。

## 验证

```sh
uv run pytest -q
node --test tests/test_chat_ui.cjs
node --check src/rust_coach/static/app.js
```

后端覆盖真实聊天、合成、拆除、状态、截图、建议链路的阶段；检查缓存与跳过检索、幂等回放、错误隔离和断开连接清理。ASGI 测试在模型仍等待时直接确认进度帧已经发出，避免只验证完成后的整段响应。前端 DOM 测试使用实际脚本和 ReadableStream，验证分片中文、实时状态、步骤列表、断流恢复与重试。测试使用替代模型，不调用付费服务；DOM 测试不等于真实浏览器布局验收。
